# AmneziaWG Telegram-бот

Управление самостоятельно развёрнутым AmneziaWG VPN через Telegram. Роли
админ/клиент/друг, инвайты, периоды подписки с блокировкой трафика при истечении,
накопительная статистика, карантин чужих пиров, условная маршрутизация
(российский IP для российских сервисов), локальный мониторинг железа хоста,
самообновление.

Пиры заводит **только бот** — он единственный источник истины по составу
конфига. Клиенты подключаются приложением Amnezia (формат `vpn://` заморожен),
но серверная сторона приложения не поддерживается: всё, что появилось в
`awg0.conf` мимо бота, считается аномалией и уходит в карантин.

Этот файл — обзор проекта и архитектуры. Дальше:

## Архитектура

Бот co-located с awg на одном хосте и управляет им локально. Единственный внешний
канал — Telegram Bot API.

**Два режима доступа к awg**, переключаются ключом `docker.runtime` в
`conf/app.yaml`:

- `host` — awg установлен на самой машине, команды идут напрямую. Основной режим;
- `docker` — команды идут через `docker exec` в контейнер Amnezia. Поддерживается
  для установок, которые ещё не переехали.

```
┌───────────────────────────────────────────────────────────┐
│  Хост (AmneziaWG + бот на одной машине)                    │
│                                                           │
│  awg-bot (systemd)                                        │
│   • Telegram Bot API   ← единственный внешний канал        │
│   • SQLite (состояние)                                    │
│   • APScheduler   опрос трафика, мониторинг, живость шлюза │
│   • inotify-вотчдог  awg0.conf                             │
│        │                                                  │
│        ▼  awg / awg-quick  (или docker exec в старом режиме)│
│  AmneziaWG: awg0.conf, iptables-блокировки по адресам      │
│                                                           │
│  метрики CPU/RAM/диск — бот читает сам: /proc + statvfs    │
└───────────────────────────────────────────────────────────┘
```

Почему только co-located: управление awg локальное (по сети до него бот не
ходит), а сам бот выходит в Telegram через тот же хост. Разносить бота на
отдельную машину смысла нет — в РФ при заблокированном Telegram такой бот терял
бы и доступ к Telegram, и к awg, то есть не закрывал бы ни одной задачи. Метрики
железа снимаются локально, без агентов и сетевых приёмников.

Переезд с контейнера на хост убирает примерно треть сложности сетевого слоя:
контейнер работал в своём netns, и различать клиентов приходилось до его
MASQUERADE. Перенос — `install/awg-host-migrate.sh`, с проверкой по факту и
откатом.

## Устройства и роли

**Устройство** = пир AmneziaWG. Тип определяется по факту (без ярлыков-прокладок):

- **управляемое** (`is_managed`) — создано ботом, приватный ключ есть: может
  выдавать ссылку/QR/файл, передавать другу, менять лимит.
- **без ключа** — пир, найденный в конфиге сервера мимо бота. Реконсиляция кладёт
  его в карантин («Устройства без профиля») и поднимает тревогу админу со звуком.
  Помечается суффиксом `*`. Ключа у бота нет и взять его неоткуда, поэтому
  выдать ссылку нельзя: только переименовать, привязать к профилю или удалить.

**Роли** (проставляет middleware по tg_id):

- **admin** (из конфига) — полный доступ ко всему.
- **client** — свой профиль: свои устройства (выдача конфигов, переименование,
  лимиты), передача устройства другу. Не может трогать чужое.
- **invited** (друг) — управляет только устройствами, которые ему расшарили
  (мультидружба: один tg_id → устройства от разных владельцев); переименование
  недоступно.

**Имена живут только в БД бота** — сервер про них не знает, в конфиге пира их
нет. Синхронизировать не с чем и не с кем.

**Первое устройство админа заводит сам бот** при первом старте: без него у
администратора не было бы доступа к боту, а созданный руками пир уехал бы в
карантин. Ссылка приходит в Telegram отдельным сообщением с кнопкой «Скрыть».

## Условная маршрутизация

Российский IP для российских сервисов — банков, госуслуг, маркетплейсов, которые
не пускают с зарубежного адреса. Помеченный трафик уходит линк-туннелем на шлюз
с российским адресом (Raspberry Pi дома), остальное выходит обычным путём с ВПС.

**На шлюз идёт только то, что в наборе.** Набор перечисляет российские сервисы;
всё прочее — заграница по умолчанию. Отсюда три свойства: домашний канал не
становится общим потолком по полосе, пустой набор безопасен (равносилен
выключенной функции), а отказ шлюза мягкий — «сервис ругается на адрес», а не
«нет интернета».

**Конфиги устройств при этом не меняются** — режим это серверное состояние, а не
отдельные учётные данные. Выданные `vpn://` продолжают работать, переключение
мгновенно и обратимо.

Флаг двухслойный: админ разрешает функцию профилю, пользователь включает её у
себя. Базовый список бот качает сам; сверх него у каждого профиля свой личный.
Живость шлюза меряется проходимостью (TCP-зонд через линк), а не возрастом
хендшейка, с порогом в три замера в обе стороны.

Пока `routing.gw_interface` пуст, функция спит целиком: UI её не показывает,
реконсиляция не трогает систему. Это же и аварийный рубильник.

Обвяз ставится скриптами: `install/routing-host-setup.sh` (ВПС),
`install/routing-link-setup.sh` (линк до шлюза, собирает готовый бандл для
второй стороны), `install/routing-gw-setup.sh` (шлюз). Диагностика —
`awg-bot routing-doctor`, она называет отказавший слой, а не просто «не
работает».

## Установка

Поставка — один архив, установщик внутри. На чистом хосте — одна команда:

```bash
curl -fsSL https://raw.githubusercontent.com/<repo>/main/install/awg-bot-install.sh | sudo bash
```

Вопрос ровно один — токен бота; кто админ, установщик выясняет одноразовым
кодом в чате. Всё остальное он делает сам: ставит AmneziaWG версии, прибитой к
поставке, создаёт сервер с нуля, разворачивает код в `/opt/awg-bot`, venv,
конфиг, секреты, systemd-сервис, спрашивает одной строкой про файервол и
печатает конфигурацию первого устройства в терминал. За собой убирает архив и
временный каталог. Дальше управление — командой `awg-bot`:

```
reconfigure  update  backup  restore  uninstall
status  start  stop  restart  logs
routing-doctor          диагностика условной маршрутизации по слоям
gw-bundle               пересобрать бандл для шлюза, не меняя ключей
awg status|install|reload|plan   ядро AmneziaWG версии, прибитой к поставке
first-device            конфигурация первого устройства админа в терминал
```

Топология не спрашивается: внешний адрес определяется сам (`ip route get`, а за
NAT — внешним запросом), порт и подсеть берутся у созданного сервера либо у
живого, если он уже стоял. Файервол — один вопрос в конце установки, дальше он
живёт в боте (⚙️ Настройки → 🛡 Файервол).

**Самообновление.** Бот раз в сутки и при старте смотрит релизы репозитория,
находит следующую версию за установленной и предлагает обновиться кнопкой:
качает ассет, сверяет sha256 и зовёт `awg-bot update`. Вторая половина
обновления исполняется уже новым кодом — иначе правка в самом скрипте не смогла
бы применить себя.

**Самопроверка на старте** (`runtime/preflight.py`) отделяет фатальное от
замечаний: без обязательных секретов и топологии бот не поднимется, а всё
остальное — недоступный IMAP, неподнявшийся шлюз, нечитаемый конфиг — уезжает
админу отдельным сообщением, не мешая работе.

## Приостановка подписки («в отпуск»)

Пауза **замораживает время**: `period_end` сдвигается вперёд на зарезервированные
дни, VPN-доступ отключается (PAUSED-каскад на клиента и устройства). Дни паузы —
**счёт у профиля** (`conf/pause.yaml`): годовая подписка получает
`pause_max_total_days` (28) при создании на год и при каждом продлении на год,
даже несвоевременном, накопление до двух таких; ежемесячная —
`monthly_pause_days` (2) за каждый своевременно оплаченный месяц (создание и
продление, пока подписка не истекла и без отсрочки), накопление до 12 таких;
смена типа переносит остаток в пределах максимума нового типа; день/неделя
счёт не пополняют, у бессрочной он всегда ноль. Ни «максимума за один
вход», ни ограничения остатком подписки нет. Списание по факту с округлением
вверх: 1 минута паузы = 1 день; неиспользованный остаток при досрочном выходе
возвращается в `period_end` и на счёт. Кнопка главного меню называется
«⚙️ Управлять подпиской», только пока есть рычаг — войти в паузу или снять
свою; иначе «📝 Моя подписка».

**Вход** (клиент, «Управлять подпиской»): выбор длительности кнопками
7/14/«весь остаток» (недоступные пресеты скрыты, дубли не показываются;
«✏️ Другое» — ввод числа 1..доступного, скрыто, когда вводить нечего) →
предупреждение о тупике (VPN выключится, выйти досрочно можно только через
бота; если Telegram доступен лишь через этот VPN — сам не выйдешь) →
подтверждение. Кнопка входа не прячется при нулевом остатке — по нажатию
объясняется: дни на счету закончились. На экране подписки — счёт
`Приостановка подписки: доступно N дней` с правилами начисления под ним; дни
не сгорают ни по какому сроку.

**Три выхода из паузы:**

1. **Кнопка «Возобновить»** в боте (клиент) — в любой момент.
2. **Админ**: в карточке клиента при активной паузе самой верхней кнопкой
   «▶️ Вывести из приостановки» — тот же пересчёт дней. Запасной выход, если
   клиент заперся.
3. **Аварийный e-mail-выход** (опционально): при входе в паузу клиенту выдаётся
   одноразовый код (8 симв., алфавит без похожих 0/O/1/l). Заперевшись без
   Telegram, клиент шлёт письмо с кодом **в теме** на настроенный адрес — бот
   опрашивает IMAP-ящик исходяще (портов на хосте не открываем), находит код,
   снимает паузу и отвечает «Код принят, доступ восстановлен». Свойства:
   `From` не является аутентификацией (спуфится) — секрет только код; тело
   письма не читается вообще; невалидный код игнорируется молча (письмо
   помечается прочитанным, ответа нет); код одноразовый и живёт только пока
   активна пауза. Настройка — целиком через визард
   (`awg-bot reconfigure` → «Настроить аварийный email-выход»): адрес ящика
   (для `@icloud.com` IMAP/SMTP подставляются сами, иначе ручной ввод),
   app-specific пароль, опциональный алиас (Enter — сам адрес ящика), интервал
   опроса (не менее 60 сек). Секреты — в env, остальное — `conf/email.yaml`; пустые
   поля = фича спит.

Авто-выход по истечении зарезервированного срока делает watchdog
(`check_pauses`); бессрочную админскую паузу (admin_open) снимает только админ.

## Объявления

Админ выбирает профили-адресаты и режим. **Простое** объявление уходит
владельцам отмеченных профилей и тем, кому они раздали устройства: их это
касается напрямую, а узнать иначе неоткуда. **С продлением подписки** — только
владельцам: перед отправкой подписка каждого продлевается на заданное число
дней (активной — конец периода + N, истёкшей — сегодня + N, бессрочной —
ничего), и к тексту у каждого своя шапка с датами. Дальше одинаково: ввод
текста (можно с картинками), превью с проверкой разметки, подтверждение, отчёт
о доставке.

## Модель конфигурации и безопасности

- **Топология и правила — в yaml** (`/etc/awg-bot/conf`): источник истины, генерит
  установщик, правится руками на холодную, переживает обновление кода. Часть
  ключей горячие — читаются в точке использования и применяются без рестарта.
- **Секреты — только в env** (`/etc/awg-bot/env`, `600`). Недостающие обязательные
  ключи ловит `config.validate()` при старте с адресным сообщением.
- **Крипто-материал AWG** (ключ сервера, psk, обфускация awg-протокола, порт)
  читается **live с сервера** и кэшируется — второго источника истины нет.
  Публичный ключ выводится из приватного, а не читается отдельным файлом:
  файл жил своей жизнью и мог разойтись с ключом молча.
- **Приватные ключи управляемых устройств** живут в БД (`/var/lib/awg-bot`);
  единственная копия вне сервера — **шифрованный бэкап** (SecretBox), если задан
  ключ/пассфраза.
- **Пер-пирный SSH-фильтр**: SSH к хосту из туннеля разрешён только с адресов
  админских устройств. Точка врезки зависит от режима — на хосте это INPUT
  (пакет на собственный адрес транзитом не идёт), в контейнере FORWARD.
  Проверять фильтр нужно **по счётчикам пакетов**: набор правил может выглядеть
  безупречно и стоять мимо потока.
- **Клиент «Администратор»** неудаляем и не ограничивается (блок/лимит/пауза
  недоступны, defense-in-depth в сервисе).
- **Файервол — одна точка**: nft-таблица `awg_bot_guard`, которую ведёт бот
  (SSH-вайтлист, изоляция пиров, NAT клиентов); секреты в env `600`.
- **Время везде UTC+3.** Сервер живёт в UTC, бот конвертирует.

## Структура (пакет по слоям)

Направление зависимостей: `core ← util ← infra ← domain ← bot ← runtime`,
`config` доступен всем. Запуск — `python -m awgbot` (обёртка `__main__.py`);
форграунд — `./run.sh`.

Разделение «чистое против грязного» проведено дважды и одинаково: `configgen`
против `awg`, `domain/routing` против `infra/routing`. Чистое тестируется без
сервера, грязное — руками.

```
awgbot/
  core/      config     чтение yaml + секреты из env, validate()
             settings   горячий кэш conf/*.yaml (правки без рестарта)
             enums, models, blocks   доменные типы, битмаски блокировок
  util/      timeutil   время UTC+3, форматтеры, формат даты Amnezia
             qrgen      QR/GIF; secrets_util  argon2id/SecretBox (крипто бэкапов)
  infra/     db         SQLite (per-thread), схема, миграции, доступ
             awg        ЕДИНСТВЕННЫЙ слой команд к awg (host | docker exec)
             routing    команды условной маршрутизации: ipset/iptables/ip/dnsmasq
             updates    релизы репозитория, сверка sha256
             email_resume  IMAP/SMTP аварийного email-выхода из паузы
  domain/    services   бизнес-логика (склейка db+awg+configgen+routing)
             configgen  генерация vpn:// и .conf (кодек формата приложения)
             routing    чистая логика: нормализация доменов, генерация dnsmasq
  bot/       texts, keyboards, guides   презентация
             filters, middleware, callbacks, states   glue aiogram
             notifier   рассылка уведомлений (пейсинг + RetryAfter)
             handlers/  роутеры client + admin/ (пакет: panel, clients, devices, gateway,
                        updates, selfops, blocks, broadcast) + friend + routing + settings + …
  runtime/   main         сборка и запуск
             preflight    самопроверка окружения на старте (fatal / warning)
             scheduler    APScheduler-задачи (трафик, сроки, монитор, живость шлюза)
             watcher      inotify-вотчдог awg0.conf (дебаунс)
             conf_watcher горячая перечитка conf/*.yaml
             routing_doctor  диагностика маршрутизации по слоям
             hostmetrics  локальные метрики железа (/proc + statvfs)
  assets/    guides/      скриншоты пошаговых гайдов (смена региона App Store)

tools/       restore_backup  расшифровка архива резервной копии на любой машине
install/     awg-bot-install.sh      установщик (он же качает поставку из трубы)
             awg.lock                версия AmneziaWG, прибитая к поставке
             awg-kernel-install.sh   сборка ядра и тулз по манифесту
             awg-server-init.sh      сервер awg с нуля на чистом хосте
             awg-host-migrate.sh     переезд с контейнера на хост
             routing-host-setup.sh   обвяз ВПС под маршрутизацию
             routing-link-setup.sh   линк до шлюза + бандл для второй стороны
             routing-gw-setup.sh     сторона шлюза
conf/        *.yaml — конфигурация; run.sh — форграунд-запуск
```

## Тесты

Пакет покрыт тестами четырёх уровней (`tests/`, pytest):

```
tests/unit/         чистая логика без БД/сети (timeutil, configgen, домены
                    маршрутизации, secrets_util, hostmetrics, awg-парсеры,
                    а также разбор самих shell-скриптов поставки)
tests/smoke/        импорт всего пакета, config.validate(), сборка aiogram-роутеров
tests/integration/  настоящая временная SQLite + фейковый awg-слой (db, services)
tests/e2e/          сквозные сценарии: жизненный цикл, лимиты трафика,
                    пауза/грейс, мониторинг, маршрутизация
```

```bash
python3 -m venv venv && ./venv/bin/pip install -r requirements-dev.txt
./venv/bin/python -m pytest              # весь набор
./venv/bin/python -m pytest -m unit      # один уровень (unit|smoke|integration|e2e)
```

Тесты не трогают сервер и Telegram: awg- и routing-слои подменяются in-memory
фейками, БД — временный файл. Установочные скрипты в CI не гоняются, но их
